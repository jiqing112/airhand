# 局域网直连 + UI 地基与连接流重设计

## Context

**需求 1（局域网直连）**：无中心 Server 的纯局域网场景下，被控端监听 `IP:端口`，控制端直接 `IP:端口` 连入；复用现有端到端安全机制（Noise 身份握手、SPAKE2 配对码）；Opt-in，不影响现有服务器流程。

**需求 2（UI）**：按 Token 重构路线（零新依赖），本期交付设计地基 + 连接流（LAN 输入的落点）+ 菜单/弹窗打磨，目标是 shadcn/Linear 级品质。

探索已确认关键事实：
- E2E 握手与传输无关（`secure::respond`/`Initiator::finish` 泛型于任意字节流，配对码 SPAKE2 完全端到端，服务器看不见）
- 会话层（`Router`/lane/数据报/`Merge`）可跑在任意 QUIC 连接上；`establish()`（controller/link.rs:46）只消费 `Router`+`Connection`
- `direct/tls.rs` 的 `Cert::generate()`、`server_config()`（any-client）、`transport()` 直接复用
- 现有缺口仅两处：host 只在打洞期间接受直连（direct/host.rs:129），且直连指纹只经加密通道交换（DirectOffer）——LAN 模式用"TLS 接受任意证书 + E2E Noise 做真认证"替代（与中转模式安全等价：中转模式下服务器证书也只是传输层）

## Part 1：局域网直连（协议 → 链路 → 客户端 → 前端）

### 1.1 协议层 `crates/airhand-proto`
- 新建 `src/lan.rs`（lib.rs 挂 mod）：
  ```rust
  /// 控制端直连后，控制通道上的第一条消息（wire 帧格式 CBOR）
  pub struct LanConnect {
      pub session_id: u64,  // 控制端生成的随机会话号
      pub init: Vec<u8>,    // HandshakeInit（Noise 第一条消息）
      pub name: String,     // 控制端设备名（审批界面显示）
      pub os: String,
  }
  ```
- 配对密码哨兵：`pake_password(code, pairing)` 两端必须用同一个 `code`（secure.rs:482/794）。定义 `LAN_CODE` 常量（两端约定），host 侧经 `Incoming.code`（host/mod.rs:105"配对时要用"）传入。安全性不弱于中转模式：中转模式下控制码对攻击者同样可见，SPAKE2 才是防离线爆破的主体。配对结果是公钥级的（`Paired{key}`），LAN 配对过的控制端在服务器模式下同样被认出

### 1.2 链路层 `crates/airhand-link`

**被控端**——新建 `src/host/lan.rs`：
- `LanConfig { bind: SocketAddr, allow: Vec<Cidr> }`；CIDR 解析小工具（可放 proto 或 link）
- 监听任务（独立于服务器连接生命周期，服务器断线时 LAN 会话照常工作）：
  1. `quinn::Endpoint::server(server_config(&Cert::generate()?), bind)`（复用 direct/tls.rs:72）
  2. accept 循环：先按 `allow` 白名单校验远端 IP（空 = 不限）→ 接受第一条单向流 → 读 16 字节 `SessionHeader` 取 session_id → 读 `LanConnect`
  3. `Router::start` + `router.register(session_id)`，把预读的流注入 inbox.control（仿 direct/host.rs accept_direct 的结构；lanes.rs 需要一个"预注入首流"的小口子）
  4. 组装 `Incoming { conn, router, session_id, init, code: LAN_CODE, peer: Peer{name,os,ip}, kick: 新 watch, approvals: 共享, direct: None }` → 交给现有 session 闭包 → `serve()`/`HostStreams::open`/`DesktopGate` 全部原样复用（配对、审批、托盘显示、会话全链路零改动）
- 启动点：`host::run()`（host/mod.rs:121）加参数 `lan: Option<LanConfig>`，在重连循环前 spawn；`HostCmd`（KickAll）需转发给 LAN 会话（第二个 mpsc 或共享 watch）
- Windows 服务模式自动获得（winsvc/agent.rs:65 走同一 `HostService::start` + 同一配置文件）

**控制端**——`controller/mod.rs` 加 `connect_addr(&self, addr, opts, ui, frontend)`：
- 解析 `host[:port]`（默认端口 4433），复用 net.rs 的 RFC8305 解析
- `direct::bind` 新端点，`lan_client_config(cert)` 拨号（SNI "airhand"）
- 控制通道上先发 `LanConnect`，再走握手（`controller/link.rs` 加 `establish_lan()`，从 `establish()` 改造：控制流已预开并写入了引导消息）
- `SessionIo` 直连专用模式：无 resume token、无打洞任务；重连 = 按 addr 重新拨号（现有 retry 循环传 `ConnectOptions.addr` 即自动获得）
- `direct/tls.rs` 加 `lan_client_config(cert)`：接受任意服务端证书的自定义 verifier（仍校验 TLS 1.3 握手签名，照 Pinned 的写法去掉指纹比对）
- `problem.rs`：`HostUnreachable`（超时/拒绝）→ 前端文案

**console 协议**（crates/airhand-link/src/console.rs）：
- `Call::Connect` 加 `addr: Option<String>`（有 addr 走 connect_addr，有 code 走服务器，互斥）
- `SessionInfo` 加 `addr: Option<String>`（前端记住设备用）
- 桌面端 `client/src-tauri/src/console.rs` 是透传，无需改动

### 1.3 桌面壳 `client/src-tauri`
- `config.rs`：`Settings` 加 `[lan]` 段——`listen = false`、`port = 4433`、`bind = ""`（可指定网卡 IP）、`allow = []`（CIDR 列表）；模板注释同步
- `host/mod.rs`：把 `config::settings().lan` 组装成 `LanConfig` 传入 `airhand_link::host::run`
- 状态/托盘：hub 状态加 LAN 监听信息，托盘菜单显示只读行"局域网直连：192.168.x.x:4433"（本机地址枚举复用 `direct::candidates()` 的本机路由地址逻辑）；开关不做进托盘（settings 读一次生效，保持"改配置重启生效"的现有约定）

### 1.4 设备记忆（两端贯通）
- `devices.rs`：`Device` 加 `addr: Option<String>`（serde 默认缺省，旧配置兼容）；去重键 = code 或 addr
- 前端 `api.ts SavedDevice.addr`、`store/devices.ts` 匹配键、`actions.ts` rememberSession 从 `SessionInfo.addr` 写入

### 1.5 前端连接流 `client/src`
- `store.ts` Draft 加 `target: string`；`api.ts ConnectOptions` 加 `addr`
- `ConnectView`（重设计的一部分，见 Part 2）：**单个智能输入框**取代"控制码 6 格 + 无处放 IP"的问题——一个 mono 大输入框自动识别：6 位纯数字 = 控制码（3+3 分组显示）；含 `.` 或 `:` = 地址（自动补默认端口）。粘贴 12 位仍拆成 控制码+配对码（保留现有行为）。零模式切换、零辅助标签，布局自解释
- `console.ts` connect() 带上 addr；`session.ts` 的会话标识/重试适配 addr 目标

## Part 2：UI 地基 + 连接流重设计（Token 路线，零新依赖）

## 验证

- Rust：`cargo test -p airhand-link`（新增 LAN 回环集成测试：握手成功、错误配对码 5 次锁定、CIDR 拒绝）；`cargo check -p airhand`（客户端 crate，工具链环境变量见前次会话）
- 前端：`npm run typecheck` + `npm run test`（node --test）；`npm run dev` + 浏览器截图自检循环（browser-use + visual-judge 对 ConnectView/设备列表各状态）
- 手动端到端冒烟：debug 构建 `airhand.exe` 开启 `[lan] listen`，同机跑 airhand-web（web 控制台的拨号发生在 web 服务进程，可达 127.0.0.1:4433）浏览器连 `127.0.0.1:4433`，验证配对码 → 画面/输入/剪贴板；真机两台局域网机器验证地址显示与重连
- 回归：服务器模式连接流程不受影响（`code` 与 `addr` 互斥分支）

## 风险与边界

- Android 端本期不含（控制端 UI 与 native 适配下期评估）
- 上游同步纪律：新增文件为主（lan.rs/proto/lan.rs/ui/），共享文件改动最小化（host::run 加参、console.rs 加字段、ConnectView 属 fork 自留地）
- Windows 防火墙：首次监听会弹系统授权，文档说明
- `LAN_CODE` 哨兵与 `Router` 预注入首流是两处协议级新概念，均有现成模式可仿（pake_password 的 code 混入、accept_direct 的首流处理），实现时以测试钉死行为
